🔴 CRITICAL — Pre-public launch (cannot ship without)

1. Real authentication

Cannot launch without this. Currently x-user-id header is trivially spoofable; password hash is plaintext "test".

  • Replace plaintext password_hash with bcrypt
  • Real registration creates users + client_profiles/worker_profiles (today: leads only, no login possible)
  • Session tokens (JWT or server-side sessions) — replacing the header-based pseudo-auth
  • Rate limiting on /api/login
  • Password reset flow

2. Email verification

Register success currently says "we'll email you" — nothing sends. Real email service needed.

  • Resend or SendGrid account
  • verification_tokens table
  • POST /api/verify-email/:token endpoint
  • Verify page in frontend
  • Gate login until email verified

3. MFA (Multi-factor authentication)

Evgeny's non-negotiable requirement for all logins. mfa_enabled column already exists.

  • TOTP (Google Authenticator) or SMS-based
  • Enrolment flow + recovery codes
  • Enforce per-role (staff/admin mandatory; clients/workers optional at first)

4. Microsoft 365 SSO (Entra ID)

Evgeny's requirement for staff logins. entra_object_id column already exists.

  • Azure App Registration in HelpHome tenant
  • Coordinator + admin roles login via SSO
  • Clients and workers stay standalone (email/password + MFA)
  • Group-based role assignment

5. Privacy Act compliance

Legal foundation for handling health-adjacent personal data.

  • Legal review of Privacy Policy + T&Cs
  • Data retention policy + destruction schedule
  • Consent capture at registration
  • Breach notification flow
  • AU data residency documented (already satisfied — Supabase Sydney)

🟠 HIGH — Required by stakeholders / meetings

6. Progress notes (legal evidence)

Mandatory per meeting. Without this, cannot legally invoice. Schema exists (progress_notes table); no UI or API yet.

  • Worker submits note after shift completion (text + photo attachments)
  • Coordinator approves / rejects
  • Immutable once approved
  • Attached to invoice as proof of service
  • Feeds Xero via VisualCare

7. VisualCare integration

Evgeny to provide API credentials + docs. Audit table exists (visualcare_sync_log); no live calls.

  • Read: clients, workers, rosters, compliance status
  • Write: shift completions, progress notes
  • Scheduled sync (nightly) + webhooks if VC supports
  • Graceful failure handling (queue + retry)

8. Payment gateway

Via VisualCare → Xero (no direct Xero calls from CareWork). Pricing model deliberately deferred to post-pilot board decision.

  • Client subscription billing
  • Contractor tax invoices
  • Integration with plan managers (PlanCare etc.)

9. Funding display in coordinator view

Schema already has funding_stream, plan_manager_name, ndis_number. Not visible in Coordinator Hub card or Client Requests.

  • Add funding tag to Coordinator Hub worker cards
  • Add funding + plan manager to Client Requests rows
